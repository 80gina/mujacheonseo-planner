## 2. 기능 요구 사항 대조

| 요구 사항 | 우리 구현 | 확인 |
|---|---|:-:|
| 최소 3개 이상 페이지/섹션, 메뉴 이동 | **8개 섹션** (홈·수업설계·활동도서관·혼자듣는수업·해설아카이브·현장진행·보관함·상태) | ✅ |
| 반응형 | 720px 이하 하단 탭바 전환, 입력칸 16px 고정(iOS 확대 방지), safe-area 대응 | ✅ |
| AI API 연동 1개 이상 (입력→결과) | **2개** — `POST /api/generate`(수업계획서), `POST /api/discover`(소재 탐색) | ✅ |
| 프론트/백엔드 구조 분리 | `public/` (HTML·CSS·JS) ↔ `api/` (Python) | ✅ |
| requirements.txt | 저장소 루트 | ✅ |
| 프론트엔드 순수 HTML/CSS/JS | **프레임워크 0개.** package.json 없음, 빌드 단계 없음 | ✅ |
| 백엔드 Vercel Serverless Functions (Python) | `api/index.py` 단일 엔트리포인트 + 4개 모듈 | ✅ |
| 실패 처리 1개 이상 | **4가지** (아래 5번 표) | ✅ |
| API 키 환경 변수 관리 | `os.environ.get("GEMINI_API_KEY")`, `.env`는 .gitignore | ✅ |
| 배포 URL에서 재현 가능 | `/api/health?probe=1` 로 상시 자가 진단 | ✅ |
| 템플릿 복제 금지 | 데이터·문구·구성 전부 자체 작성 | ✅ |

## 5. 실패 처리 검증표 — 직접 눌러보고 체크

| # | 상황 | 시험 방법 | 나와야 하는 것 | ☑ |
|:-:|---|---|---|:-:|
| 1 | 빈 입력 | 「수업 설계」에서 제목을 비우고 버튼 클릭 | "수업 제목을 입력해 주세요" 경고, 요청 안 나감 | ☐ |
| 2 | API 4xx | (서버가 자동 처리) 키가 없으면 401, 잘못된 값이면 400 | 빨간 알림에 사유 표시 | ☐ |
| 3 | 지연·타임아웃 | 45초가 지나면 자동 중단 | "시간이 오래 걸립니다" 안내 | ☐ |
| 4 | 사용량 한도(429) | 「웹 검색으로 근거 찾기」를 켜고 여러 번 실행 | 검색만 자동으로 끄고 계속 진행 | ☐ |

## 6. 구술 대비 — 질문 ↔ 답변 위치

| 예상 질문 | 결과보고서 위치 | 한 줄 답변 |
|---|---|---|
| 왜 프레임워크를 안 썼나 | Ⅳ-1 | 요구 사항이기도 하지만, 빌드 없이 파일만 올려도 도는 구조라 유지가 쉽습니다 |
| AI 연동은 어떻게 했나 | Ⅳ-3 | 프론트가 `/api/generate`로 보내면 파이썬이 Gemini에 물어보고 JSON으로 돌려줍니다 |
| 실패 처리는 몇 가지인가 | Ⅳ-4 | 네 가지 — 빈 입력, 4xx/5xx, 45초 타임아웃, 429 자동 완화 |
| API 키는 어떻게 관리했나 | Ⅳ-5 | 환경 변수로만. **실제로 유출을 겪고 폐기·재발급 후 이중 차단을 넣었습니다** |
| 쿼터는 어떻게 고려했나 | Ⅳ-6 | 웹 검색을 기본 끔으로 두고, 429가 나면 검색만 끄고 재시도합니다 |
| 남과 다른 점이 무엇인가 | Ⅴ | AI가 만든 자료를 그대로 안 쓰고, **틀린 것을 왜 뺐는지까지 앱에 전시**합니다 |
| 가장 어려웠던 것은 | Ⅷ-2 | Vercel의 새 파이썬 런타임이 엔트리포인트를 하나만 허용해 구조를 다시 짰습니다 |
