# Ⅰ. 과제 개요

## 1. 무엇을 만들었나

숲해설 수업계획서를 AI로 설계하고, 현장에서 진행하고, 해설가 없이도 들을 수 있게 하는 웹 서비스입니다.

여덟 개 섹션으로 되어 있습니다.

| 섹션 | 하는 일 |
|---|---|
| 홈 | 서비스 소개와 네 단계 프레임워크 |
| **수업 설계** | 조건을 채우면 **AI가 수업계획서 초안을 생성** |
| 활동 도서관 | 20개 활동 모듈 + **AI 소재 탐색** |
| **혼자 듣는 수업** | 해설가 없이 듣는 자율 코스 6종 · 정거장 29곳 |
| **해설 아카이브** | 사실 확인을 거친 자료 11갈래 |
| 현장 진행 | 단계별 음성 타이머 |
| 보관함 | 저장·인쇄·내보내기 |
| 상태·진단 | AI 연결 자가 점검 |

## 2. 왜 만들었나

저는 숲해설을 합니다. 수업계획서를 쓸 때마다 같은 일을 반복했습니다.
소재를 정하고, 연령에 맞게 시간을 나누고, 안전 지침을 쓰고, 화두를 붙입니다.
**한 번 만드는 데 두세 시간이 걸리고, 그 대부분이 매번 똑같은 작업**입니다.

그리고 현장에는 다른 문제가 있습니다.
숲해설 프로그램은 예약제이고 인원이 차야 열립니다.
**자연에 관심이 있어도 해설가를 만나지 못하는 사람이 훨씬 많습니다.**

이 두 가지를 한 앱에서 풀고 싶었습니다.
해설가에게는 준비 시간을 줄여 주고, 해설가를 못 만나는 사람에게는 앱이 대신 안내하는 것입니다.

## 3. 과제의 두 축

| 축 | 내용 |

## Ⅳ-3. AI API 연동 기능이 1개 이상 있고 입력→결과 출력이 되는가

### ✅ 확인됨 — 2개

| 엔드포인트 | 입력 | 출력 |
|---|---|---|
| `POST /api/generate` | 제목·대상·인원·시간·계절·장소·활동유형·모듈 | 수업계획서 JSON (요약·화두·목표·흐름표·준비물·안전·성찰·확장) |
| `POST /api/discover` | 소재 키워드 (예: 반딧불이) | 활동 모듈 초안 + 출처 |

**데이터 흐름**

```
사용자 입력
  → planner.js 가 검증 후 fetch('/api/generate')
  → api/index.py 가 route 분기
  → api/generate.py 가 프롬프트 조립
  → Gemini API 호출
  → JSON 정리
  → renderPlan() 이 화면에 표
```

**확인 절차**: 수업 설계에서 제목을 넣고 「AI로 수업계획서 만들기」

**결과**: 4~6단계 흐름표, 각 단계의 화두, 준비물, 안전 지침이 표로 나옵니다. 그 자리에서 고쳐 쓸 수 있고(`contenteditable`), 저장·인쇄됩니다.

**증빙**: `03_AI동작.png`

### 왜 그렇게 했는가

**AI를 두 군데 쓴 이유**가 있습니다.
`generate`만 있으면 앱에 든 20개 모듈 안에서만 수업을 만들 수 있습니다.
`discover`를 붙여서 **목록에 없는 소재도 다룰 수 있게** 했습니다.
위키백과에서 배경 자료를 먼저 모으고, 그것을 근거로 모듈 초안을 만듭니다.

**결과를 고쳐 쓸 수 있게 한 이유**는, AI 결과를 그대로 쓰면 안 되기 때문입니다.
현장 안전과 종 동정은 반드시 해설가가 최종 확인해야 합니다.
그래서 화면 아래에 그 문구를 고정으로 띄웁니다.

### 📋 요약

| 구분 | 내용 |
|---|---|
| **현재 동작** | 조건 입력 → Gemini 호출 → 계획서 표 출력 → 편집·저장·인쇄 |
| **선택 이유** | ① 정해진 목록에 갇히지 않게 ② 결과는 초안이지 완성이 아니라서 |
| **탈락 후보** | SDK(`google-generativeai`) — 의존성 하나를 더 늘리고 싶지 않았습니다 |

## Ⅳ-4. 실패 처리가 1개 이상 구현되어 있는가

### ✅ 확인됨 — 4가지

| # | 상황 | 처리 | 코드 위치 |
|:-:|---|---|---|
| 1 | **빈 입력** | 요청을 보내기 전에 막고 경고. 제목 없음/120자 초과/시간이 숫자가 아님/20~300분 밖 | `planner.js collectPayload()` + `generate.py handle()` |
| 2 | **API 오류 4xx·5xx** | 401(키 없음) · 400(입력 오류) · 502(응답 이상)를 갈라서 각각 다른 문구 | `_common.py call_gemini()` |
| 3 | **지연·타임아웃** | `AbortController`로 45초에 요청을 끊고 안내 | `planner.js sendRequest()` |
| 4 | **사용량 한도 429** | 검색 그라운딩만 끄고 같은 모델로 재시도 | `_common.py` |

**추가 안전장치** — 응답이 왔는데 화면 그리기가 실패해도 로딩에 갇히지 않게 했습니다.

```javascript
let requestSeq = 0;              // 요청 번호표
const mySeq = ++requestSeq;
...
if (mySeq !== requestSeq) return;   // 늦게 온 옛 응답은 버림
try { renderPlan(currentPlan); }
catch (renderErr) { showError(...); return; }
finally {
  // 어떤 경로로 끝나도 로딩 화면은 반드시 내림
}
```

**확인 절차**: 수업 설계에서 **제목을 비운 채** 버튼을 누릅니다.

**결과**: "수업 제목을 입력해 주세요" 경고가 뜨고 요청이 나가지 않습니다.

### 왜 그렇게 했는가

**앞뒤 양쪽에서 검사하는 이유**가 있습니다.
프론트에서만 막으면 개발자 도구로 우회할 수 있고, 서버에서만 막으면 헛된 API 호출이 나갑니다.
**호출 한 번이 곧 비용**이라 앞에서 먼저 거릅니다.

**429를 다르게 다룬 이유**는 진단으로 알아낸 것입니다.
처음엔 429가 나면 다음 모델로 넘어가게 했는데, 계속 실패했습니다.
`/api/health?probe=1`을 만들어 세 가지 요청 형태를 시험해 보니
**웹 검색 그라운딩에만 별도의 작은 무료 한도**가 있었습니다.
모델 문제가 아니라 도구 문제였습니다. 그래서 모델은 그대로 두고 검색만 끄게 고쳤습니다.

### 📋 요약

| 구분 | 내용 |
|---|---|
| **현재 동작** | 빈 입력·4xx/5xx·45초 타임아웃·429 자동 완화 + 렌더 실패 대비 |
| **선택 이유** | ① 앞뒤 이중 검사로 비용 절약 ② 429는 모델이 아니라 도구 문제 |
| **탈락 후보** | 429에서 모델 전환 — 실제로 해봤고 틀렸습니다. 진단으로 바로잡았습니다 |

## Ⅳ-5. API 키를 환경 변수로 관리하고 코드·README·스크린샷에 노출하지 않았는가

### ✅ 확인됨 — 다만 **유출을 실제로 겪고 대응했습니다**

이 항목은 솔직하게 씁니다. 숨기면 같은 일이 또 생깁니다.

**무슨 일이 있었나**

Vercel 환경 변수 `GEMINI_MODEL` 자리에 모델 이름 대신 API 키가 들어갔습니다.
그 값이 공개 진단 화면 `/api/health`의 `modelCandidates` 배열에 그대로 실려 나갔습니다.

```json
"modelCandidates": ["AQ.Ab8RN6IN…(키)", "gemini-3.5-flash-lite", …]
```

**어떻게 발견했나**

배포 확인을 위해 `/api/health`를 열었다가 첫 번째 값이 모델 이름이 아닌 것을 봤습니다.
자가 진단 엔드포인트를 만들어 둔 것이 유출을 잡아낸 셈입니다.

**어떻게 대응했나**

| 순서 | 조치 |
|:-:|---|
| 1 | Google AI Studio에서 해당 키 **즉시 폐기** |
| 2 | 새 키 발급 후 Vercel 환경 변수 교체 |
| 3 | `GEMINI_MODEL` 변수 자체를 삭제 |
| 4 | 코드에 **이중 차단** 추가 |
| 5 | Redeploy 후 노출이 사라진 것을 확인 |

**넣은 이중 차단**

① **들어올 때 거른다** — `safe_model_name()`

```python
_MODEL_RE = re.compile(r"^[a-z0-9][a-z0-9.\-]{2,59}$")
_SECRETISH = ("aiza", "aq.", "sk-", "ya29.", "ghp_", "bearer")
```

모델 이름의 형태(`gemini`/`gemma`로 시작, 3~60자)를 만족하고
비밀값처럼 보이지 않을 때만 후보로 받습니다.

② **나갈 때 지운다** — `redact()`

| 지우는 것 | 결과 |
|---|---|
| `?key=…` | `?key=[숨김]` |
| `AIza…` `AQ.…` `ya29.…` `sk-…` | `[숨김]` |
| `Bearer …` | `Bearer [숨김]` |
| 환경 변수에 실제로 든 값과 일치하는 문자열 | `[숨김]` |

구글의 오류 메시지가 요청 URL을 통째로 되돌려 주는 경우가 있어서 ②가 필요합니다.

**검증**: 유출된 값을 환경 변수에 넣은 채 `health.handle()`을 실행해 응답에 키가 없음을 확인했습니다. 6종 패턴 전부 통과.

**현재 상태** (누구나 확인 가능)

```
https://mujacheonseo-planner.vercel.app/api/health
→ modelCandidates 에 gemini- 로 시작하는 이름만
```

**코드·문서 점검**

| 대상 | 결과 |
|---|---|
| 소스 코드 | 키 문자열 0건. `os.environ.get()`으로만 읽음 |
| README | 키 없음. 발급 방법만 서술 |
| `.env` | `.gitignore`에 등록 |
| `.env.example` | 빈 값 + "여기에 API 키를 넣지 마세요" 주석 |
| 커밋 이력 | 키가 커밋된 적 없음 (`GEMINI_MODEL`은 Vercel 대시보드에만 있었음) |

**증빙**: `10_진단.png`

### 왜 그렇게 했는가

과제 지침에 "키 유출이 의심되면 즉시 폐기·재발급"이 있습니다.
**실제로 그 상황을 겪고 절차대로 대응한 것**이 이 항목의 답입니다.

그리고 한 가지를 배웠습니다.
**"키를 코드에 안 쓴다"만으로는 부족합니다.**
환경 변수를 잘못 넣는 사람의 실수까지 코드가 막아야 합니다.
그래서 값의 형태를 검사하고, 나가는 문장까지 한 번 더 훑습니다.

### 📋 요약

|---|---|

## Ⅳ-6. AI API의 과금·쿼터를 인지하고 호출 빈도와 실패 상황을 고려했는가

### ✅ 확인됨

| 장치 | 내용 |
|---|---|
| **웹 검색 기본 끔** | 그라운딩은 무료 한도가 매우 작습니다. 체크박스로 **선택했을 때만** 씁니다 |
| **앞단 검증** | 빈 입력은 호출 자체를 안 합니다 |
| **중복 요청 차단** | 요청 중에는 버튼이 비활성화됩니다 |
| **429 자동 완화** | 한도에 걸리면 검색만 끄고 재시도 |
| **모델 우선순위** | 무료 한도가 넉넉한 `flash-lite` 계열을 앞에 둠 |
| **타임아웃 45초** | 매달린 요청이 자원을 붙잡지 않게 |
| **`maxOutputTokens` 제한** | 진단 호출은 16토큰으로 |

**실측 근거** — `/api/health?probe=1` 결과

| 요청 형태 | 상태 |
|---|:-:|
| 검색 그라운딩 | **429** (할당량 초과) |
| JSON 강제 | 200 ✅ |
| 단순 형태 | 200 ✅ |

같은 키로 같은 모델인데 **검색을 붙일 때만 429**가 납니다. 검색 그라운딩의 한도가 따로 있다는 증거입니다.

### 왜 그렇게 했는가

처음에는 검색을 항상 켜 두었습니다. 근거 있는 계획서를 만들고 싶어서요.
그런데 몇 번 쓰지도 않았는데 429가 쏟아졌습니다.

`probe`를 만들어 세 형태를 나눠 시험해 보고 나서야 원인을 알았습니다.
**추측으로 고쳤으면 계속 엉뚱한 곳을 만졌을 겁니다.**
그래서 지금은 검색을 기본 끔으로 두고, 체크박스 옆에 "무료 한도 주의"라고 적어 두었습니다.

### 📋 요약

| 구분 | 내용 |
|---|---|
| **현재 동작** | 검색 기본 끔 · 앞단 검증 · 중복 차단 · 429 완화 · 45초 제한 |
| **선택 이유** | 실측으로 검색 그라운딩만 한도가 작다는 것을 확인 |
| **탈락 후보** | 검색 상시 켜기 — 실제로 해봤고 429가 났습니다 |

## Ⅳ-7. 프론트엔드와 백엔드 구조가 구분되어 있는가

### ✅ 확인됨

```
mujacheonseo-planner/
├── public/            ← 프론트엔드
│   ├── index.html
│   ├── css/style.css
│   ├── js/  (11개 파일)
│   ├── manifest.webmanifest
│   └── sw.js
├── api/               ← 백엔드 (파이썬)
│   ├── index.py       ← 유일한 엔트리포인트
│   ├── _common.py     ← Gemini 호출 · 위키 수집 · 마스킹
│   ├── generate.py    ← 수업계획서
│   ├── discover.py    ← 소재 탐색
│   └── health.py      ← 진단
├── docs/
├── requirements.txt
├── pyproject.toml
└── vercel.json
```

**연결 방식**

```json
{ "rewrites": [
  { "source": "/api/generate", "destination": "/api/index?route=generate" }
]}
```

### 왜 그렇게 했는가

**`api/index.py` 하나로 모은 것은 자발적 선택이 아니라 대응이었습니다.**
Vercel의 새 파이썬 런타임은 프로젝트당 엔트리포인트를 **하나만** 허용합니다.
처음엔 `generate.py`·`discover.py`·`health.py`를 각각 함수로 두었는데 배포가 실패했습니다.

그래서 `index.py`가 `?route=` 값을 보고 나눠 부르는 구조로 다시 짰습니다.
각 모듈은 `handle()` 함수 하나만 내놓습니다. **파일은 나뉘어 있고 입구만 하나**입니다.

### 📋 요약

| 구분 | 내용 |
|---|---|
| **현재 동작** | `public/` ↔ `api/` 분리, 입구는 `index.py` 하나 |
| **선택 이유** | Vercel 새 런타임의 제약. 모듈은 나누고 입구만 합침 |
| **겪은 오류** | `No python entrypoint found` → 구조 재설계 (커밋 4·5) |

방문자 추적을 붙이면 그 원칙이 깨집니다.
**가점 하나보다 원칙의 일관성을 택했습니다.**

# Ⅶ. 오류 및 수정 이력

## 1. Vercel 함수 런타임 오류

| | |
|---|---|
| **증상** | `Error: Function Runtimes must have a valid version` |
| **원인** | `vercel.json`에 `"runtime": "python3.12"`를 버전 표기 없이 씀 |
| **해결** | 해당 설정을 제거 (커밋 2) |
| **배운 것** | 오류 메시지가 "valid version"이라 말하면 형식 문제입니다 |

## 2. 엔트리포인트 하나만 허용 ★ 가장 어려웠던 것

| | |
|---|---|
| **증상** | `No python entrypoint found. Add [tool.vercel] entrypoint` |
| **원인** | 새 파이썬 런타임은 프로젝트당 진입점 **하나만** 허용 |
| **해결** | `api/index.py`로 통합, `?route=`로 분기 (커밋 4~6) |
| **배운 것** | 플랫폼 제약은 우회가 아니라 **구조 재설계**로 풀어야 합니다 |

## 3. 정적 파일까지 파이썬이 삼킴

| | |
|---|---|
| **증상** | 루트(`/`)를 열어도 API의 405 JSON이 나옴 |
| **원인** | 파이썬 함수가 모든 경로를 받음 |
| **해결** | 화면 파일을 `public/`으로 옮기고 + `index.py`에도 정적 서빙 추가 (커밋 7) |
| **배운 것** | 한 겹만 믿지 않고 두 겹으로 막았습니다 |

## 4. AI 502 — HTTP 404

| | |
|---|---|
| **증상** | "통신 오류 (502) … (HTTP 404)" |
| **원인** | 모델 이름이 계정·시기마다 다른데 하나로 고정 |
| **해결** | 후보 목록 순회 + `ListModels`로 실제 목록 조회 후 자동 선택 (커밋 8~9) |
| **배운 것** | 외부 API의 이름은 바뀝니다. 목록을 물어보는 쪽이 안전합니다 |

## 5. 429 폭주 — 첫 처방이 틀렸던 사례

| | |
|---|---|
| **증상** | "호출이 너무 잦습니다" 반복 |
| **첫 처방** | 429가 나면 다음 모델로 전환 → **효과 없음** |
| **진짜 원인** | `?probe=1`로 시험해 보니 **웹 검색 그라운딩에만 별도의 작은 한도**가 있었음 |
| **해결** | 모델은 그대로 두고 검색만 끄고 재시도. 검색을 선택 사항으로 (커밋 15) |
| **배운 것** | **추측으로 고치면 엉뚱한 곳을 만집니다.** 진단 도구를 먼저 만드는 게 빨랐습니다 |

## 6. 결과가 나왔는데 로딩 화면에 갇힘

| | |
|---|---|
| **증상** | 계획서가 만들어졌는데 화면은 계속 로딩 |
| **원인** | 렌더링 중 예외가 나면 로딩을 내리는 코드까지 도달하지 못함 |
| **해결** | 요청 번호표 + `try/catch` + `finally` 강제 탈출 + 결과로 자동 스크롤 (커밋 16) |
| **배운 것** | "성공했을 때"만 생각하면 안 됩니다. **끝내는 코드는 항상 `finally`에** |

## 7. API 키 노출 ★ 가장 아찔했던 것

| | |
|---|---|
| **증상** | `/api/health`의 `modelCandidates`에 API 키가 그대로 노출 |
| **원인** | Vercel 환경 변수 `GEMINI_MODEL`에 모델 이름 대신 키를 입력 |
| **해결** | 키 즉시 폐기·재발급 → 변수 삭제 → `safe_model_name()`·`redact()` 이중 차단 (커밋 19) |
| **배운 것** | **"코드에 키를 안 쓴다"만으로는 부족합니다.** 사람의 실수를 코드가 막아야 합니다 |

## 4. 배운 것

세 가지가 남았습니다.

**하나.** 웹 서비스는 만드는 것보다 **배포해서 계속 돌아가게 하는 것**이 어렵습니다.
커밋 20개 중 14개가 배포와 연동을 붙이는 데 들어갔습니다.

**둘.** **문제를 추측하지 말고 볼 수 있게 만들어야 합니다.**
429의 원인을 세 번 잘못 짚었습니다. 진단 엔드포인트를 만들고 나서 5분 만에 알았습니다.

**셋.** **AI는 빠르지만 틀립니다.** 그리고 틀린 것이 아주 그럴듯합니다.
"예천 회룡포 백송(천연기념물)"은 실재하지 않는데도 완벽한 문장으로 나왔습니다.
AI를 쓰는 사람에게 필요한 것은 생성 능력이 아니라 **확인하는 습관**이라는 걸 배웠습니다.
