| **타겟** | 숲해설가, 환경/생태 강사, 초·중등 교사, 창의적 체험활동 기획자 |

| (구) 활동 모듈 | 12종 (A~L) — 상처와 나이테, 때를 아는 지혜, 서식지 리모델링, 질경이, 기생과 공생, 죽음이 만드는 숲, 전나무, 은행나무, 당산나무, 팽나무, 금강소나무, 관방제림 |
| (구) 설계 3축 | ① 주제별 관심사 9종(예술·문화·철학·음악·과학·공학·역사·문학·치유) ② 프로그램 유형 4종(숲해설·숲활동·숲치유·숲여행) ③ 연령 구분 7종 |

| **차별점** | 저장·인쇄에서 끝나지 않고 **현장 음성 진행 모드**까지 이어짐 |

> 설계 사상: 본 서비스는 "사용자 입력 → fetch 요청 → AI 서버 처리 → 화면 출력 및 예외 처리"의

## 1. 서비스 목적

### 1-1. 문제 정의

숲해설 현장에서 흔히 관찰되는 세 가지 문제가 있습니다.

| 문제 | 현장의 모습 |
|---|---|
| **도감형 수업** | "이건 느티나무예요"로 시작해 이름 맞히기로 끝난다 |
| **설계 부담** | 대상·계절이 바뀔 때마다 계획서를 처음부터 다시 쓴다 |
| **철학의 단절** | 좋은 활동은 있으나 '왜 이 활동인가'를 설명하지 못한다 |

### 1-2. 해결 방향

> 숲을 **식물 도감**이 아니라 **살아 있는 교실(講學相長)** 로 설계하도록 돕는다.

생태 현상(상처·나이테·기생·순환)을 입력하면, 그와 맞닿는 사유의 갈래와
아이들에게 던질 화두, 몸으로 하는 오감 활동을 한 벌로 묶어 내놓습니다.

### 1-3. 성공 기준

| 지표 | 목표 |
|---|---|
| 계획서 1건 작성 시간 | 기존 40~60분 → **5분 이내** |
| 생성된 계획서의 현장 사용률 | 저장 건수 대비 인쇄/현장진행 실행 50% 이상 |
| AI 실패 시 이탈 | 실패 안내 후 재시도율 70% 이상 |

├── 2. 수업 설계 (#design)          ★ AI 기능

│     활동 모듈 12종 / 관심사·활동유형 2중 필터 / 카드 클릭 → 설계 폼 자동 반영
│     철학 개념 사전 18종 (개념어 ↔ 생태 현상 대응표)
│     수업하기 좋은 노거수 6곳 (연계 모듈 표시)
│     추천 도서·자료 18종
├── 4. 현장 진행 (#field)           ★ 음성 기능
│     계획서 선택 / 음성 설정 / 단계 타이머 / 단계 목록
└── 5. 보관함 (#archive)
      검색 / 열기 · 인쇄 · 진행 · 삭제 / JSON 내보내기·불러오기

**이동 방식** : 상단 고정 헤더의 메뉴 버튼. 단일 페이지에서 섹션을 교체하는 방식(SPA 유사)이며,
`location.hash` 를 갱신해 뒤로가기와 새로고침에도 같은 화면이 유지됩니다.
모바일(720px 이하)에서는 햄버거 메뉴로 접힙니다.

## 3-A. 설계의 세 축 (v1.2 신설)

같은 느티나무 한 그루라도, **누가 · 어떤 창으로 · 어떤 형식으로** 만나느냐에 따라
전혀 다른 수업이 됩니다. 본 서비스는 이 세 가지를 입력 축으로 삼습니다.

### ① 주제별 관심사 (9종, 복수 선택)

| 관심사 | 보는 창 (AI 프롬프트에 그대로 주입) |
|---|---|
| 🎨 예술 | 색·형태·질감·구성의 눈으로 보고, 자연물 자체를 재료 삼아 표현 |
| 🏮 문화 | 세시풍속·민속·생활사 속 쓰임과 이름의 유래 |
| ☯ 철학 | 무용지용·연기·제행무상·격물치지 등 고전 개념으로 다시 묻기 |
| 🎵 음악 | 숲의 소리·리듬·침묵을 듣고 몸의 박자로 옮기기 |
| 🔬 과학 | 관찰 → 측정 → 가설 → 검증으로 원리 확인 |
| ⚙ 공학 | 생물의 구조를 설계 문제로 보고 흉내 내어 만들기(생체모방) |
| 📜 역사 | 이 땅과 나무가 겪은 사건, 사람과 숲의 관계 변화 |
| ✍ 문학 | 감각한 것을 시와 이야기로 옮기고 은유를 스스로 만들기 |
| 🌿 치유 | 호흡·감각 이완·느린 걸음으로 몸과 마음의 회복 |

> 관심사를 여러 개 고르면 AI는 **한 단계에 하나씩 배분**해 수업 전체가 여러 결을 갖게 합니다.
> 활동 도서관에도 같은 관심사 필터가 걸려 있어, 모듈을 관심사로 찾을 수 있습니다.

### ② 프로그램 유형 (4종, 단일 선택)

| 유형 | 설계 무게중심 |
|---|---|
| **숲해설** | 해설가의 설명과 화두가 중심. 관찰 → 질문 → 이야기 나눔의 비중이 큼 |
| **숲활동** | 만들기·놀이·신체 활동 중심. 손과 몸을 쓰는 시간이 60% 이상 |
| **숲치유** | 이완·명상·호흡 중심. 말수를 줄이고 침묵과 감각에 시간을 씀 |
| **숲여행** | 코스 탐방 중심. 이동하며 지점마다 짧게 멈추는 구성 |

### ③ 연령 구분 (7종, 단일 선택)

| 연령 | 집중 지속 | 설계 기준 |
|---|---|---|
| 유아 (5~7세) | 10분 | 한 문장 15자 이내. 흉내와 놀이 위주. 입에 넣는 사고 최우선 차단 |
| 초등 저학년 | 15분 | 직접 만지고 세어 보기. 추상어 대신 비유 |
| 초등 고학년 | 20분 | 왜인지 묻고 추리. 모둠 토론 가능 |
| 중·고등학생 | 25분 | 철학 개념어 직접 사용. 논쟁형 화두 |
| 성인 / 일반 | 30분 | 자기 경험과 잇는 성찰 시간을 길게 |
| 시니어 | 20분 | 이동 거리·경사 축소, 앉을 자리 사전 확보 |
| 가족 단위 | 20분 | 어른–아이 짝 활동으로 구성 |

**집중 지속 시간은 AI 프롬프트에 그대로 전달되어, 한 단계가 그 길이를 넘지 않도록 제약합니다.**
연령은 화면 표시용 라벨이 아니라 **실제 설계 제약**으로 쓰입니다.

## 3-B. 수업의 뼈대 — 네 단계 프레임워크 (v1.3 신설)

AI가 `flow`(수업 흐름)를 짤 때 이 순서를 뼈대로 삼습니다.
단계 이름과 개념어가 그대로 프롬프트에 들어가며, 생성된 계획서의 흐름표가 이 순서를 따릅니다.

| 단계 | 철학 개념 | 수업 내 적용 |
|---|---|---|
| **관찰 (格物)** | 격물치지 | 한 포기·한 그루를 지극히 관찰해 생명의 이치를 스스로 발견하게 한다 |
| **관계 (緣起)** | 연기법 · 관찰자 효과 | 관찰자와 대상이 서로 영향을 주고받는 상호창조적 관계를 이해한다 |
| **태도 (受容)** | 제행무상 · 취착 | 늙음과 아픔 같은 변화를 긍정하고 집착을 내려놓는다 |
| **성장 (道法)** | 솔성지위도 | 각자의 본성대로 때를 기다리며 스스로 피어나게 한다 |

## 3-C. 해설 모드 3종 (v1.3 신설)

같은 계획서라도 **말의 높이**가 달라야 합니다. 연령 구분이 *설계 제약*이라면, 해설 모드는 *문체 제약*입니다.

| 모드 | 프롬프트에 주입되는 지시 |
|---|---|
| **키즈·청소년 모드** | 쉬운 용어와 스토리텔링 중심. 퀴즈·미션 형식을 섞고, 개념어 대신 이야기로 풀어 쓴다 |
| **일반·성인 모드** | 다학제적 깊이를 살린 인문 교양 해설. 철학 개념어를 그대로 쓰고 성찰 시간을 길게 둔다 |
| **전문가·해설사 모드** | 해설가가 그대로 읽을 수 있는 현장 스크립트와 식물학·공학 데이터, 진행 팁을 함께 제공 |

## 3-D. 난이도 조정 축 (v1.4 신설)

같은 활동도 학년에 따라 **규칙**이 달라야 합니다. PDF 자료의 "게임 규칙 및 난이도 조정 가이드"를
이동 범위·이동 방식·미션·안전 4축으로 압축해 프롬프트 제약으로 넣었습니다.

| 난이도 | 프롬프트에 주입되는 지시 |
|---|---|
| **쉬움** (유아·초등 저·가족) | 이동 범위는 인솔자 시야 안. 뛰지 않고 빠른 걸음까지. 미션은 한 번에 하나. **정적인 역할에도 반드시 몸을 쓰는 동작을 준다.** 안전요원 별도 배치 |
| **표준** (초등 고·청소년) | 숲길 주요 동선까지 이동. 달리기 허용. 미션 2단계 이상. 스마트폰 사용 시 전방 주시 반복 강조 |
| **심화** (중·고등·성인) | 논쟁형 화두와 자료 해석. 신체 활동은 줄이고 관찰 기록과 토론 시간을 늘림 |

> "가만히 서 있는 역할은 아이가 금방 흥미를 잃는다"는 현장 지적을 그대로 규칙으로 옮겼습니다.

## 3-E. 사실 검증 장치 (v1.4 신설)

AI 생성물과 참고 자료에는 **틀린 사실이 섞일 수 있습니다.** 이를 구조로 막았습니다.

| 장치 | 내용 |
|---|---|
| **모듈 `caution` 필드** | 20개 모듈 중 8개에 "해설 전 확인 사항"을 달았습니다. 오개념이 생기기 쉬운 지점을 미리 못 박습니다 |
| 화면 표시 | 도서관 카드와 설계 폼, 생성된 계획서 세 곳에 ⚠ 박스로 함께 노출 |
| 프롬프트 제약 | ① 출처를 확인할 수 없는 구체 수치(흡수량·면적·연도)는 쓰지 않는다 ② 모듈의 확인 사항을 어기지 않는다 |
| 자료 채택 기준 | 참고 PDF의 문학·미술 목록 중 **실재가 확인된 것만** 채택. 미확인 항목은 앱에 넣지 않음 |

### 바로잡은 오개념 (참고 자료 → 앱 반영 시 수정)

| 참고 자료의 서술 | 앱에 반영한 내용 |
|---|---|
| "모기가 초콜릿을 만든다" | 카카오의 수분 매개자는 **등에모기과(Ceratopogonidae)**의 소형 파리류이지 모기(Culicidae)가 아님 |
| 재선충이 "수관(樹冠)을 막는다" | 막히는 것은 **물관(가도관)**. 수관은 잎이 달린 윗부분 |
| "재선충 = 미세한 벌레" | **선충(線蟲)**. 곤충이 아님 |
| 청설모를 외래종으로 전제 | 청설모는 **토종**. 그 통념 자체가 수업 소재 |
| 왕벚나무 자생지 단정 | 제주 자생 왕벚나무와 소메이요시노의 관계는 **학계 논쟁 중**으로 표기 |
| 숲가꾸기 색 표시 의미 단정 | 사업·관할에 따라 다를 수 있어 **사전 확인** 문구 추가 |
| 수종별 탄소 흡수량 수치 인용 | 출처마다 다르고 탄소량/CO₂량 혼동이 잦아 **수치를 앱에서 제거**, 확인 안내로 대체 |

## 3-F. 자료 수집형 확장 — 목록에 갇히지 않는 설계 (v1.5 신설)

### 문제

활동 모듈 20종은 잘 다듬은 목록이지만, 숲에서 만나는 소재는 그보다 훨씬 많습니다.
"오늘 반딧불이를 봤는데 이걸로 수업을 짜고 싶다"는 요구를 목록이 막아서는 안 됩니다.

### 해결 — 두 번째 AI 엔드포인트 `POST /api/discover`

```
[사용자가 소재 입력]  예) 반딧불이
   ↓ js/discover.js  fetch('/api/discover')
[api/discover.py]
   ① 위키백과 API 로 배경 자료 수집  (키 불필요, ko.wikipedia.org)
        · 검색 → 상위 2건의 요약문(최대 1200자)과 문서 URL 확보
   ② Gemini 호출 시 **구글 검색 그라운딩** 도구를 함께 켬
        tools: [{ "google_search": {} }]
        → 모델이 웹에서 근거를 찾아 답하고, groundingMetadata 에 출처가 실려 옴
   ③ 위키 출처 + 검색 출처를 합쳐 활동 모듈 초안과 함께 반환
   ↓
[화면]  모듈 초안 카드 + **참고한 자료 목록(링크)**
   ↓  [＋ 내 모듈로 저장]  →  localStorage
[활동 도서관·수업 설계 폼에 '내 모듈'로 합류]
```

### 수집 경로 두 가지를 함께 쓰는 이유

| 경로 | 강점 | 약점 | 대비책 |
|---|---|---|---|
| **위키백과 API** | 키 불필요, 응답이 빠르고 안정적, 출처 URL이 명확 | 최신 정보가 아닐 수 있음, 문서가 없는 소재도 많음 | 실패해도 조용히 넘어가고 ②만으로 진행 |
| **구글 검색 그라운딩** | 최신 자료, 모델이 스스로 검색어를 만들어 확인 | 모델·지역에 따라 도구를 못 쓸 수 있음 | 400 응답이면 **검색 없이 한 번 더 자동 재시도** |

> 그라운딩을 켜면 JSON 강제 출력 모드(`responseMimeType`)를 함께 쓸 수 없어,
> 프롬프트로 JSON 형식을 요구하고 `extract_json()` 이 코드펜스·잡담을 걷어냅니다.

### 수업 설계 폼에서도 자유 소재

`숲의 소재` 선택지 맨 아래에 **「✎ 직접 입력 — AI가 자료를 모아 설계」** 를 두었습니다.
고르면 소재 입력칸이 열리고, `/api/generate` 가 같은 방식(위키백과 + 검색 그라운딩)으로
모듈 없이 처음부터 계획서를 만듭니다.

### 출처 표시 — 확장의 안전장치

자료를 넓히면 **틀린 내용이 섞일 위험도 함께 커집니다.** 그래서 이렇게 막았습니다.

| 장치 | 내용 |
|---|---|
| 참고한 자료 목록 | 모듈 초안과 생성된 계획서 모두에 **근거 링크**를 함께 표시. 인쇄물에도 남습니다 |
| `factNote` 필드 | 탐색 결과에 "확인한 것 / 확인하지 못한 것"을 AI가 한 줄씩 구분해 적습니다 |
| `caution` 자동 생성 | 종 동정·보호수 여부·관찰 가능성이 불확실하면 확인 사항으로 남깁니다 |
| 프롬프트 제약 | 출처를 확인할 수 없는 구체 수치는 쓰지 않는다 / 확인 못 한 것은 단정하지 않는다 |
| 「AI 생성」 배지 | 내 모듈은 도서관에서 주황 배지로 구분되어, 검증된 기본 모듈과 섞이지 않습니다 |

### 더 붙일 수 있는 자료원 (향후)

| 자료원 | 얻는 것 | 필요 조건 |
|---|---|---|
| 국립수목원 국가생물종지식정보시스템 | 국명·학명·분포·형태 | data.go.kr 인증키 |
| 산림청 산림공간정보 / 등산로 API | 답사지 좌표·난이도·주의구역 | data.go.kr 인증키 |
| 기상청 단기예보 API | 수업 당일 강수·기온 → 우천 대안 자동 생성 | data.go.kr 인증키 |
| 국가문화유산포털 | 천연기념물·보호수 지정 여부 | 공개 API |

지금 구조(`api/_common.py` 에 수집 함수를 모아 둠)에서는 함수 하나를 더 쓰고
프롬프트에 한 줄 붙이면 끝나므로, 확장 비용이 낮습니다.

## 3-G. 모바일 우선 전환 (v1.6 신설)

숲해설은 **책상이 아니라 숲에서** 진행됩니다. 그래서 설계 도구가 아니라 **현장 도구**가 되도록 바꿨습니다.

### ① 앱으로 설치 (PWA)

| 구성 | 파일 | 하는 일 |
|---|---|---|
| 앱 정보 | `public/manifest.webmanifest` | 이름·아이콘·시작 주소·세로 고정·테마색 |
| 오프라인 | `public/sw.js` | 화면 파일을 기기에 저장. `/api/` 는 항상 네트워크 |
| 설치 안내 | `public/js/pwa.js` | `beforeinstallprompt` 를 받아 **＋앱 설치** 버튼 노출 |
| 아이콘 | `icon-192 / 512 / maskable.png` | 외부 라이브러리 없이 zlib 로 직접 생성 |

**오프라인 경계** — 한 번 연 화면·보관함 계획서·타이머·음성 안내는 **인터넷 없이 작동**합니다.
AI 생성과 소재 탐색만 인터넷이 필요하므로, 출발 전에 만들어 저장하는 사용 흐름을 안내합니다.

### ② 한 손 조작 레이아웃 (720px 이하)

| 항목 | 처리 |
|---|---|
| 하단 탭바 5개 | 홈·설계·도서관·현장·보관함. 엄지가 닿는 위치에 고정 |
| 터치 대상 | 버튼 최소 44px, 탭 56px |
| 입력칸 글자 | **16px 고정** — 그 미만이면 iOS 가 화면을 확대해 버림 |
| 안전 영역 | `env(safe-area-inset-*)` 로 노치·홈바 회피 |
| 타이머 카드 | `position:sticky` 로 스크롤해도 시간이 보임 |
| 화면 꺼짐 | 현장 진행 화면에서 **Wake Lock** 으로 화면 유지 |

### ③ 상태 · 진단 화면 (6번째 섹션)

AI가 안 될 때 원인을 **비개발자도 찾을 수 있게** 만든 화면입니다.

## 5. 데이터 항목 (DB 설계)

| `season` | enum | 봄/여름/가을/겨울 | 가을 |
| `place` | string | 장소 특성 | 도시숲 산책로 |
| `philosophy` | string | 철학적 배경 | 위리안치 |
| `activityTypes` | string[] | 활동 유형 | ["오감 관찰","신체 모사·놀이"] |

### 5-2. `flow[]` (수업 단계) — plan 1 : N

| 필드 | 타입 | 설명 |
|---|---|---|
| `time` | string | 소요 시간 표기 ("10분", "5~10분") |
| `name` | string | 단계 이름 |
| `activity` | string | 해설가가 실제로 시키는 일 |
| `question` | string | 이 단계에서 던질 화두 |
| `materials` | string | 이 단계 준비물 |

> 현장 진행 모드는 `time` 문자열을 `parseMinutes()` 로 초 단위 정수로 바꿔 타이머에 씁니다.
> 범위 표기("5~10분")는 평균값을 취합니다.

### 5-3. `module` (활동 모듈 — 앱 내장 마스터 데이터, `js/data.js`)

| 필드 | 타입 | 설명 |
|---|---|---|
| `id` | string (PK) | A ~ F |

### 7-3. 실패 처리 기준

| 구분 | 조건 | HTTP | 사용자 안내 | 복구 방법 |
|---|---|---|---|---|
| 빈 입력 | 숲의 소재 미선택 | (프론트 차단) | **경고 팝업** "숲의 소재와 학습 대상을 모두 선택해 주세요!" | 해당 입력칸 포커스 + 빨간 테두리 |

| 빈 입력 | 활동 유형 0개 | (프론트 차단) | "최소 한 가지를 선택해야 합니다" | 체크박스로 이동 |
| 값 범위 | 시간 20~300분 밖 | 400 | 범위 안내 | 값 수정 |
| 인증 | 키 없음/오류 | 401 | "환경 변수를 확인해 주세요" | Vercel 설정 후 Redeploy |
| 한도 | 쿼터 초과 | 429 | "1분 뒤 다시 시도" | [다시 시도] 버튼 |

| 형식 | JSON 파싱 실패 | 502 | "올바른 형식을 만들지 못했습니다" | [다시 시도] 버튼 |
| 지연 | 서버 40초 초과 | 504 | "응답이 오지 않았습니다" | [다시 시도] 버튼 |
| 지연 | 12초 경과 | — | **로딩바 + "응답이 지연되고 있습니다. 잠시만 기다려 주세요..."** | 계속 대기 |
| 지연 | 프론트 45초 초과 | — | "응답이 너무 늦습니다" | `AbortController` 로 중단 후 재시도 |

> **중복 호출 방지** : 요청 중에는 생성 버튼을 `disabled` 로 잠급니다.
> **비용 관리** : `maxOutputTokens 4096` 으로 상한을 두고, 무료 등급 기준 분당 호출 한도를
> 넘으면 429 안내로 사용자를 멈춰 세웁니다.

## 3-H. 해설 아카이브 — 사실 확인을 거친 자료층 (v1.7 신설)

### 배경
숲해설 자료를 생성형 AI로 대량 수집하면 분량은 금방 채워지지만, 지명·수종·지정 여부가
섞여 들어옵니다. 실제로 이번에 수집한 「노거수 40선」을 국가유산포털·위키백과와
대조한 결과, 40건 중 **18건이 오기이거나 근거를 찾을 수 없는 항목**이었습니다.

### 설계 원칙
분량을 채우기 위해 틀린 것을 남기지 않습니다. 대신 **왜 뺐는지를 앱 안에 남깁니다.**
확인을 통과하지 못한 항목은 삭제되어 사라지는 것이 아니라
「정정 기록」 탭에 사유와 함께 전시됩니다. 해설가에게는 이것 자체가 교재가 됩니다.

### 구성 (5개 탭 · `public/js/corpus.js`)

| 탭 | 내용 | 수량 | 검증 |
|---|---|---|---|
| 6대 분류 | 습성·형태·자생지·쓰임·전설·귀화 | 60 키워드 | 일반 식물학 용어 |
| 화두 50선 | 화두명 + 현장 질문 + 관찰 지점 | 50 | 고전 출전 확인 |
| 노거수 | 지역·수종·지정·해설 한 줄 | 33 | 국가유산포털 교차 확인 |
| 3박 4일 코스 | 동선·주요 노거수·화두·해설 포인트 | 10 | 미확인 나무 제외 후 재구성 |
| 정정 기록 | 뺀 항목과 그 사유 | 18 | — |

### 대표적인 정정 사례

| 원자료 | 확인 결과 |
|---|---|
| 예천 회룡포 백송(천연기념물) | 실재하지 않음. 예천의 지정목은 천향리 석송령·금남리 황목근 |
| 하동 쌍계사 최치원 묘소 앞 전나무 | 쌍계사에 최치원의 묘소는 없음 (진감선사탑비 비문을 지었을 뿐) |
| 합천 해인사 학사대 전나무 | 2019년 태풍으로 도복, 천연기념물 지정 해제 |
| 강릉 오죽헌 세한송 | 근거 없음. 오죽헌의 지정목은 율곡매 |
| 고창 선운사 도솔암 느티나무 | 실제 수종은 소나무(장사송) |
| 청도 매전면 대천리 은행나무 | 은행나무는 이서면 대전리, 매전면에 있는 것은 처진소나무 |

### 수업 설계와의 연결
- 화두 카드의 **[이 화두로 수업 설계]** → 화두명이 제목에, 현장 질문과 관찰 지점이 추가 요청란에 실립니다.

  AI가 앱과 **같은 어휘로 관찰 지점을 잡도록** 유도합니다. (전부 쓰라는 지시가 아니라 우선 고려 대상으로 넣습니다)

## 3-I. 사용 대상의 확장 — 해설가 없이도 듣는 수업 (v1.8 신설)

### 문제
지금까지 이 앱은 **해설가가 쓰는 도구**였습니다. 그런데 실제 현장의 수요는 두 갈래입니다.

1. 소규모 숲해설사 — 혼자 준비하고 혼자 진행합니다. 계획서를 만들 시간이 없습니다.
2. 해설가를 만나지 못하는 사람 — 자연에 관심은 있으나 프로그램은 예약제이고, 인원이 차야 열립니다.
   초등학생·청소년·성인·가족이 여기 해당합니다.

두 번째 집단은 지금까지 이 앱에서 할 일이 없었습니다.

### 해결 — 「혼자 듣는 숲수업」 (`public/js/solo.js`)
앱이 해설가를 대신합니다. 대상을 고르고 코스를 시작하면,
정거장마다 **찾기 → 해 보기 → 들어보기 → 물음 → 답**의 다섯 단계로 진행합니다.

| 요소 | 설계 |
|---|---|
| 대상 5종 | 초등 저학년 / 초등 고학년 / 청소년 / 성인 / 가족 |
| 문장 자동 조정 | 초등 대상이면 개념어 뒤에 쉬운 말을 덧붙이고(`EASY` 사전), 저학년은 해설을 세 문장까지만 읽습니다 |
| 코스 5종 | 습성 읽기 / 형태와 과학 / 학명 / 화두 / 시민과학 (총 23개 정거장) |
| 장소 조건 | 특별한 답사지가 필요 없습니다. 동네 공원·학교·아파트 단지에서도 되도록 설계했습니다 |
| 음성 | Web Speech API로 해설을 읽어 줍니다. 이어폰을 끼고 걸으며 듣는 것을 전제로 합니다 |
| 진행 저장 | localStorage에 대상·코스·정거장을 저장해, 다음에 이어서 시작합니다 |
| 답 감추기 | 물음에 먼저 스스로 답한 뒤 「답 보기」를 누르게 합니다. 정거장을 넘기면 다시 감춥니다 |
| 마무리 | 한 문장 기록을 남기고 저장합니다. "적지 않으면 사흘 안에 사라집니다" |

### 두 갈래의 연결
자율 코스는 막다른 길이 아닙니다. 마무리 화면의
**[이 코스로 수업계획서 만들기]** 를 누르면 코스의 제목·장소·정거장이
「수업 설계」 폼에 실려, 해설가가 자기 대상과 시간에 맞는 계획서로 다시 만들 수 있습니다.
**혼자 듣던 사람이 해설하는 사람이 되는 경로**를 앱 안에 두었습니다.

### 안전 카드
혼자 나서는 사용자가 늘면 안전이 곧 기능이 됩니다.

## 3-J. 그리스 신화 — 이름 속에 남은 이야기 (v1.9 신설)

### 왜 넣는가
학명은 라틴어와 그리스어로 되어 있고, 그 상당수가 그리스 신화에서 왔습니다.
붓꽃의 Iris는 무지개의 여신이고, 작약의 Paeonia는 신들의 의사이며,
어수리의 Heracleum은 헤라클레스입니다. **학명이 어려운 암기 대상이 아니라
이야기의 저장고**라는 것을 보여 주면, 학명 수업의 문턱이 크게 낮아집니다.

### 설계 원칙 — 세 갈래로 가른다
신화와 학명을 뭉뚱그리면 곧바로 틀린 말이 됩니다. 그래서 갈래를 나눴습니다.

| 갈래 | 뜻 | 예 |
|---|---|---|
| ① 속명이 신화에서 온 식물 | 학명 자체가 신화 인물에서 유래 | 붓꽃 *Iris*, 작약 *Paeonia*, 어수리 *Heracleum*, 수련 *Nymphaea*, 톱풀 *Achillea* |
| ② 신화에 나오지만 학명은 무관 | 이야기는 진짜, 학명은 라틴 일반명 | 참나무·피나무(필레몬과 바우키스), 은백양(레우케), 월계수, 사이프러스 |
| ③ 숲에서 만나는 동물과 소리 | 현장에서 실제로 만남 | 호반새 *Halcyon*, 거미 *Arachnida*, 메아리, 큰곰자리 |

총 **22항목**, 그중 **14항목이 우리 숲에서 실제로 만날 수 있는 것**입니다.
각 항목에 `자생 / 식재 / 남부·온실 / 보기 어려움 / 밤하늘` 배지를 달아,
해설가가 **오늘 이 자리에서 쓸 수 있는 이야기인지** 바로 판단하게 했습니다.

### 사실 확인에서 걸러낸 것
그리스 신화 소재는 인터넷에 오류가 특히 많습니다. 확인 결과 12항목에 주의 표기가 붙었고,
5항목은 아예 뺐습니다.

| 걸러낸 것 | 사유 |
|---|---|
| 아칸서스와 님프 아칸타 | **고전 전거가 전혀 없는 현대의 창작**. 속명 *Acanthus*는 그리스어 akantha(가시)에서 옴 |
| 코린트식 기둥의 아칸서스 | 신화가 아니라 **비트루비우스가 전하는 건축 일화** |
| "아네모네 = 아도니스의 피" | 어원의 통설은 anemos(바람). 어원으로 제시하면 오류 |
| 리카온과 늑대 | 우리 숲에서 만날 대상이 없음 |
| 담자리꽃나무(*Dryas*)와 드리아드 | 속명은 잎이 참나무를 닮아 붙은 것이고, 남한에 자생하지 않음 |

**가장 좋은 소재는 오히려 어긋난 자리입니다.**
다프네가 변한 나무는 월계수(*Laurus nobilis*)인데, 정작 *Daphne* 속은 서향·팥꽃나무입니다.
린네가 잎이 월계수를 닮은 상록 관목에 그 이름을 붙이면서 이름이 옮겨 갔습니다.
이 어긋남을 감추지 않고 그대로 이야기하면, **학명이 왜 필요하고 왜 완벽하지 않은지**가
한 번에 설명됩니다. 앱은 이 어긋남을 지우지 않고 전시합니다.

그 밖의 주의 표기 예:
- 복수초 — 붉은 피 유래는 유럽 종의 것. **우리 복수초는 노란색**이며, 스스로 열을 내 눈을 녹입니다
- 수수꽃다리 — 속명은 님프 이름이 아니라 syrinx(속 빈 줄기·피리)에서. 남한 자생 여부는 이견
- 쑥 *Artemisia* — 여신 아르테미스설과 카리아의 여왕 아르테미시아 2세설이 병존
- 수선화 *Narcissus* — 신화 연결은 문화적으로 굳었으나 **어원 자체는 논쟁 중**
- 히아신스 — **신화 속의 그 꽃은 오늘날의 히아신스가 아닐 가능성이 큼**
- 거미·메아리 — 인물이 단어를 낳은 것이 아니라 **같은 어근을 공유**함 (서술 방향 주의)
- 사이프러스 — 우리가 '사이프러스'라 부르는 것은 대개 편백·화백·측백으로 **다른 속**

### 자율 코스 연계
「혼자 듣는 숲수업」에 여섯 번째 코스 **「신화가 남긴 이름」**(정거장 6곳)을 추가했습니다.
붓꽃 → 복수초 → 수수꽃다리 → 서향 → 참나무와 피나무 → 계곡의 호반새 순서로,
**공원과 수목원에서 실제로 찾을 수 있는 것만** 정거장으로 삼았습니다.

각 신화 카드의 **[이 이야기로 수업 설계]** 를 누르면 인물·이야기·현장 관찰 가능 여부와
주의 사항이 함께 AI 프롬프트에 실려, 사실이 어긋난 수업계획서가 생성되지 않게 막습니다.
