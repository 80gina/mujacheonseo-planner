

## 21. 배포해도 옛 화면이 보이던 결함 (v2.5)

선택함을 올린 뒤 배포 주소에서 **담기 버튼이 보이지 않는다**는 제보를 받았습니다.
파일은 GitHub 에도 Vercel 에도 올바르게 올라가 있었습니다. **범인은 서비스 워커였습니다.**

`sw.js` 는 화면 파일을 **캐시 먼저(cache-first)** 로 돌려주고 있었습니다.
숲속에서 신호가 약해도 앱이 열리게 하려던 설계인데, 그 대가로
**새로 배포해도 기기에 저장된 옛 `index.html` 과 옛 `corpus.js` 가 계속 나왔습니다.**

새로 고침 한 번이면 풀리는 문제지만, **그걸 알아야만 쓸 수 있는 앱은 곤란합니다.**
동료가 배포 URL 로 접속해 테스트해야 하는 과제라면 더욱 그렇습니다.

### 고친 방법 — 파일 성격에 따라 나눔

| 대상 | 방식 | 이유 |
|------|------|------|
| `html · css · js`, 화면 이동 | **네트워크 먼저** → 실패하면 캐시 | 코드는 늘 최신이어야 합니다. 망이 없으면 곧바로 캐시로 넘어가 오프라인도 그대로 됩니다 |
| 그림 · `lessons.json` | **캐시 먼저** (그대로) | 바뀌는 일이 드물고 109KB 라, 매번 받으면 느려집니다 |

캐시 이름도 `mujacheonseo-v5` → `v6` 으로 올렸습니다.
`activate` 에서 이름이 다른 캐시를 모두 지우므로, **이미 옛 화면을 보고 있던 기기도 다음 접속에 정리됩니다.**

### 배운 것

오프라인 지원과 최신 배포는 **맞바꾸는 관계**입니다.
「전부 캐시 먼저」는 오프라인만 보고 고른 답이었고, 배포를 보지 않은 답이었습니다.
**파일마다 어느 쪽이 더 중요한지가 다릅니다.**
